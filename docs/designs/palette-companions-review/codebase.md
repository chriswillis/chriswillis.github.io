# Observability-Brainstormer — raw report

No blockers identified at concept stage. Recommendations below concern local reproducibility and explainability; no backend telemetry is needed.

- **Major — Observability & operational debuggability: reproducible project state.** Current `hashOf()` saves seeds, palette ID, step, mode, name and format; imported palettes exist only in browser storage. Companion selections, accepted suggestions, edits and preview settings introduce state that existing links cannot reproduce. Recommend a versioned project snapshot containing reference identity/version, generator settings, selected column IDs, accepted edits and diagnostic settings. Decide whether imported reference data travels in a downloadable project, share link, or neither. Preserve the existing visible warning for unavailable references. Require deterministic replay for the chosen supported mechanism.
- **Major — Observability & operational debuggability: explain why a companion changed.** The engine already provides seed-relative colorfulness (`sRaw`), neutral classification, gamut clipping, extrapolation, excluded/interior ramps and dropped anchors. The concept does not yet define which of these explain companion suggestions. Recommend concise per-column provenance: reference hue, suggested versus accepted versus manually edited status, reason for adjustment, and material gamut/lightness compromises. This extends the existing verdict’s useful approximation and omitted-anchor explanations. Decide whether colorfulness is transferred from the original brand input or the generated brand ramp, and what happens for near-neutral brands or extreme inputs.
- **Major — Observability & operational debuggability: inspectable accessibility results.** Contrast is currently calculated against explicit palette poles and ramp endpoints; exports can convert wide-gamut values into rounded/clipped sRGB. Recommend that each new metric identify the actual foreground/background or color pair, selected step, calculation color representation and simulation mode. Distinguish measurements of the original colors from simulated previews. Decide which ramp step supplies categorical colors and whether diagnostics evaluate exported sRGB fallbacks as well as the working gamut. Otherwise a reported result cannot explain a visibly different exported chart.
- **Major — Observability & operational debuggability: observable reset and failure behavior.** Reference preservation is accepted, but “reset” could mean restore authored reference, regenerate from current brand settings, or restore the last accepted suggestion. Recommend defining and displaying that destination before implementation. Existing import/delete writes fail visibly and transactionally, whereas ordinary `save()` catches storage failures silently. With substantial edits, recommend visible unsaved-state feedback and retention of the last valid committed project when suggestion, validation or persistence fails. Keep preview, export scope and successful-copy/download feedback tied to that same committed state.
- **Nit — Observability & operational debuggability: regression evidence.** The existing VM harness provides useful local-state, precision, invalid-input, persistence-failure and import-race coverage, plus `window.__ramp` inspection. Extend it with replay, suggestion acceptance/reset, immutable-reference and export-scope invariants. Browser checks remain necessary for actual CVD rendering and preview behavior because the harness mocks the DOM. Treat this as a verification recommendation, not an implementation-readiness blocker.
